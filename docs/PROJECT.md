# 稳忆 SteadyMem

正式题目：**《稳忆：固定预算下递归工作记忆的持续更新与关联保持》**。

整理日期：2026 年 10 月 13 日。本文件归档此前讨论，定义项目长期沿用的研究问题、范围、约束与验收口径。项目目前处于问题诊断与方案筛选阶段，**尚无本项目新算法的实证结果**。候选路线、预期收益与继续投入的门槛均应与已有论文结果分开表述。

## 1. 项目要回答的问题

模型在固定持久记忆字节预算下，持续接收新信息和合法修订；写入时不知道以后会出现的具体问题。它能否正确保存新关联、更新发生变化的关联，同时保持其他仍然有效的关联，并在随后出现的问题中正确使用这些信息？

这里的记忆是**推理过程中的状态记忆**，例如递归关联状态、有限缓存、路由索引及维护元数据。研究对象是模型如何组织、写入和读取这些状态，而不是修改预训练模型权重。训练可以用于学习记忆机制，但部署阶段的每次事实变更不应要求重新训练模型参数。

项目从 Kimi Delta Attention（KDA）等递归关联记忆出发。KDA 的 delta 更新本身已具有纠错写入和查询读取能力，不能把问题描述成“线性注意力不会更新或不能按问题读取”。需要诊断的是：有限状态中哪些关联因新写入、衰减、容量竞争或访问方式而失效，局部更新是否损伤其他关联，以及修订能否真正进入最后的答案。[Kimi Linear](https://arxiv.org/abs/2510.26692)

项目保持问题导向。A、B、C 是待比较的算法候选，既不预设多 bank 分流一定成立，也不要求最终成果必须是三条路线中的某一条。

## 2. 目标场景与最小例子

目标场景是持续执行长任务的 Agent：工具观察、项目配置、任务约束、路径与接口等信息交错到来，其中一部分会被后续操作修订。Agent 需要继续使用已有有效信息，减少重复读工具和重复塞入上下文的成本。

例如，Agent 先得到两条工具观察：

| 时点 | 输入 | 当前有效关联 |
| --- | --- | --- |
| 1 | 项目甲的工作目录为 `old` | 甲 → `old` |
| 2 | 项目乙的数据目录为 `data-b` | 甲 → `old`；乙 → `data-b` |
| 3 | 项目甲已完成迁移，工作目录改为 `new` | 甲 → `new`；乙 → `data-b` |

随后才提出具体问题或执行请求：访问项目甲应使用 `new`，访问项目乙仍应使用 `data-b`。记住甲的旧目录、把两个项目混在一起、更新甲时损坏乙、或者把甲整体忘掉，都没有完成要求。

还要区分真正修订与相似表达：“项目乙改为 `new`”“考虑以后迁移甲”“引用甲原来的目录”均不能自动覆盖甲的当前值。第一阶段使用明确、可程序判定的实体和修订语义；别名、含蓄表达、来源冲突与生效时间在后续逐步加入，分别报告识别误差。

这个例子只是诊断载体。真正的场景指标应包括任务完成正确率、执行结果、重复工具调用、输入上下文量、服务延迟和每成功任务成本。

## 3. 范围与约束

### 3.1 当前主线

主线是**当前有效事实的持续新增、合法更新与未更新关联保持**。具体要求如下：

1. 输入以因果顺序处理，任何写入和状态维护只能读取已到达的信息。
2. 写入时未知具体未来问题。允许已知任务领域或操作类型，不允许用最终问题、答案或未来修订标签决定保存内容。
3. 每请求持久状态受预先声明的总字节预算约束；不能通过持续增加历史槽位、原文、KV 或元数据绕过限制。
4. 新值安装、旧值替换与非目标保持同时检验，不能只优化其中一项。
5. 第一阶段在明确语义和顺序下定义当前真值。消息到达时间与事件生效时间不同、多个来源权威冲突等情况须单独建模，不能以“最后出现”代替全部有效性判断。
6. 评估既包括未见实例，也包括未见查询改写、实体组合、负载和修订模式，避免只学习固定生成模板。

历史版本问答、精确记录删除、多跳推理、完整枚举及复杂时间推理属于后续扩展。它们可以用来检查边界，但当前不以同时解决这些问题为立项目标。

### 3.2 记忆预算的计量

预算按真实字节计量，声明 dtype、层数、头数和请求数。持久记忆包括递归矩阵、有限 KV、当前块持久缓冲、路由代表、保护地址、bank 管理信息、转移摘要、依赖图，以及任何跨查询保留的索引或记录。

模型权重作为共享模型成本单独报告；模型参数和骨干变化也要公开。训练激活、运行时临时空间和峰值显存另外报告，不能因不属于持久状态就忽略它们。若研究整个混合模型，其他注意力层的 KV 也计入每请求状态；不能把单个递归层固定容量推广为整个模型固定容量。

CPU、SSD 和外部服务上的原文、索引与版本信息同样是资源。它们可以作为部署方案或强基线，但必须报告存储、写入维护、检索、传输和重算成本。比较中应区分“严格固定持久预算的机制实验”与“允许不同资源组合的系统比较”。

### 3.3 能力上限与非目标

固定有限记忆不能无损保存无限多个独立随机事实。项目要证明的是在明确负载、信息熵和质量门槛下更有效地使用资源，并给出饱和与退化区域。

本项目不把以下主张作为目标或默认保证：

- 无限历史、任意未来问题的无损保存。
- 仅凭状态更新就保证自然语言实体绑定和修订理解正确。
- 不再输出旧值便等于新值已正确安装，或等于精确遗忘。
- 只提高单针召回、平均检索分数或某项榜单成绩便证明持续工作记忆成立。
- 通过增加容量、额外监督或更昂贵检索获得收益，却将其全部归因于新更新机制。
- 删除模型参数中的知识、恢复“某记录从未出现”的完整模型状态，或纠正该记录已引发的外部行为。

固定旧摘要的重组与完整轨迹重算不是同一性质；后续表示、卷积状态和其他层可能已受早期内容影响。精确记录删除需要独立的参考轨迹、证明和审计。[Exact Record Omission](https://arxiv.org/html/2609.06872v3)

## 4. 实际意义与外部方案的边界

稳忆的价值需要落到三个方面：长任务做得更正确；减少重复工具读取和重复上下文处理；在服务质量要求下提高状态驻留效率和有效吞吐。理论 FLOPs 或单头状态大小只能解释机制，不能单独证明部署价值。

项目必须认真比较以下可用方案：

| 方案 | 已能解决的部分 | 与稳忆比较时需要检查的边界 |
| --- | --- | --- |
| 结构化当前值表与事件日志 | 在可靠实体、属性和更新规则下明确覆盖当前值，保留可审计来源 | 自然语言如何绑定到结构；字段是否足以表达任务信息；抽取、维护和查询成本 |
| 原文记录与 RAG | 保存可重新读取、引用和核查的证据；检索可加版本或有效时间过滤 | 召回、更新识别和读者仍可能出错；历史存储、索引、检索和重新预填充的完整成本 |
| 重新调用工具 | 直接读取当前环境，避免使用已失效观察 | 工具调用是否廉价、稳定、允许重复；是否有延迟、额度、不可重复观察或外部副作用 |
| 递归工作记忆 | 在模型内部持续维护有限状态，直接参与后续计算 | 固定字节下能保留多少有效信息；更新是否损伤其他关联；是否有可用吞吐和实现成本 |

事件日志加当前物化视图是已有架构方式；检索系统也已有元数据过滤，Agent 记忆系统已有时间有效性及冲突更新。因此，“让旧证据失效”不是 KDA 独有问题，也不能作为稳忆的唯一创新依据。[Event Sourcing](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)、[检索过滤](https://learn.microsoft.com/en-us/azure/search/vector-search-filters)、[Zep](https://arxiv.org/html/2501.13956v1)

外部系统也不能免费获得正确语义：明确结构的版本更新与从自然语言推断更新关系是两种难度。应先在可靠关系下比较机制，再比较各自学习或抽取这些关系的误差与成本。

若结构化表、原文检索或廉价重读在目标场景下更准、更便宜，应接受它们作为实际推荐。稳忆值得继续投入的条件是：内部有限状态维护带来可独立验证的质量或资源优势，而不只是系统形式更复杂。

## 5. 成功标准与评价口径

### 5.1 联合正确率 JointAcc

每个评估 episode 包含新增关联、合法修订关联和未更新关联。在历史处理结束后提出未在写入时暴露的问题，构成查询集合 `Q_new`、`Q_update`、`Q_keep`。Episode 的联合成功定义为这些查询全部满足当前真值；JointAcc 是联合成功 episode 的比例：

\[
\operatorname{JointAcc}=\frac{1}{N}\sum_{e=1}^{N}
\mathbf{1}\!\left[\forall q\in Q_{e,\mathrm{new}}\cup Q_{e,\mathrm{update}}\cup Q_{e,\mathrm{keep}},\ \hat a(q)=a^*(q)\right].
\]

使用固定的各组查询数量，或按数量分层报告，避免查询集合大小改变导致指标不可比。同时分别报告新增准确率、更新准确率、未更新关联保持率、旧值误答率和无依据回答率，以定位联合失败的原因。非目标受损率应在更新前可正确回答的关联上测量；各方法还须在相近目标更新成功率下比较，防止用“不更新”换取表面的保护效果。

如果任务要求拒答，把正确拒答写进程序真值和评分规则，同时报告覆盖率；不能以减少回答掩盖记忆丢失。

### 5.2 有效容量与资源帕累托

有效容量是在预先确定的正确率门槛下，能够稳定维护的独立活跃关联数。报告容量时固定总记忆字节，并声明值的随机性、实体相似度、更新密度、历史距离、查询数量和查询改写方式。90% 等门槛属于可预注册的评估选择，不是通用自然语言任务的默认能力保证。

比较应形成质量与资源的帕累托曲线：同字节下是否更准，同质量下是否更省状态，或者在相同服务时限下是否完成更多正确任务。至少报告每请求持久字节、峰值显存、GPU 时间、CPU/SSD 开销、预填充与解码延迟、p50/p95 延迟、吞吐和失败率。系统场景进一步报告重复工具调用、输入 tokens 和每成功任务总成本。

正式实验前在开发集锁定质量门槛、非目标退化容忍度和资源约束；不能看完测试集再挑选验收定义。所有提升均注明对照配置、种子、配对区间与未匹配资源。

### 5.3 支持项目成立所需的证据

至少需要证明：

1. 基线在目标负载下确实存在新增、修订或保持的可复现失败，而骨干在短上下文中具备解题能力。
2. 干预改善对应失败，且不是仅由额外容量、额外训练数据或 oracle 信息解释。
3. 在固定总字节及合理计算对照下，联合正确率、有效容量或资源帕累托形成稳定优势。
4. 优势能够迁移到至少一个对应的自然语言或工具观察场景，并保持一般能力与非目标事实。
5. 工程实现的完整成本支持预期用途；单独成立的算法证据与尚未实现的服务收益分别陈述。

## 6. 条件候选与可能贡献

| 候选 | 检验的机制 | 成立所需证据 | 当前约束 |
| --- | --- | --- | --- |
| A：约束写入与选择性保护 | 局部新写入会损伤仍有效关联，可用有限保护降低副作用 | 匹配更新成功率、计入保护状态后，非目标受损仍减少 | 保护地址选择、释放和合法覆盖可能成为瓶颈；邻近写入改进较多 |
| B：固定预算的状态组织与干扰分流 | 多关联共享状态的竞争可由组织方式降低 | 在同总字节下超过扩大状态、静态分区、hash 与简单路由，且低频及跨区关联不退化 | 多 bank 可能只是容量拆分；动态管理和路由未必比简单组织有效 |
| C：保留必要修订的历史转移重组 | 选择旧转移时可能遗漏后续纠正 | 相同缓存和实际读取量下，必要修订闭包比普通选块、补近期、全后缀和当前/历史双表示更有效 | 历史块、依赖图、合并与回退成本较高；理想闭包也不保证完整语义正确 |

少量精确 KV、分块、路由和多记忆分支可以作为对照或可选组件；这些组合本身已有近邻，不能只凭加入模块认定创新。HLA 已研究查询条件化的完整仿射块转移，HLA-WM 已研究历史选块与时序重组；C 需要证明的是必要修订约束的独立价值。[HLA](https://arxiv.org/html/2610.05842v1)、[HLA-WM](https://arxiv.org/html/2610.05739v1)

候选贡献可能落在可复现的失败诊断、有限字节下的更新机制或组织方法、非目标保持与容量边界、以及可执行的资源比较协议。项目不承诺所有贡献同时成立，也不预先给出新算法提升幅度或成功概率。

## 7. 研究推进与证据管理

先建立纯 KDA 和简单强基线，独立扫描活跃关联数、键相似度、更新频率、距离与信息熵，区分写入干扰、衰减、容量饱和、访问失败、修订不一致和推理失败。不要仅通过拉长文本制造一个混合失败现象。

随后分别做最小机制诊断。Oracle 保护地址、分流或依赖图只提供可行上限；它们不能留在部署评测中代替真实绑定能力。若 oracle 有效而学习策略无效，应把瓶颈定位到选择或关系识别；若简单同预算基线已解释收益，应收窄或停止相应机制主张。

仅在这些证据成立后再考虑语言模型训练、规模扩展与成熟模型适配；最后进入 Agent 场景。此前讨论的 8 张 H100 80GB 是可用研究资源条件，不是必须消耗的配额，也不构成算法有效或全部路线都值得预训练的证据。

每次研究决策保存问题、假设、基线、预算、预注册指标、结果、失败案例和停止理由。区分“原论文已报告结果”“本项目假设”“验收目标”和“本项目运行结果”。没有实证时保持不确定性；没有测试不等于保证成功，也不等于保证失败。

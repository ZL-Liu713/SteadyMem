# KDA 有限记忆的选择性维护：研究问题、算法方案与实验计划

整理日期：2026 年 10 月 12 日。资源条件：8 张 H100 80GB。文档性质：基于当前讨论和一手论文整理的研究方案，尚未执行所述新算法实验。

## 1. 研究定位与当前结论

本研究希望解决的问题是：在固定或受限的记忆预算下，模型持续接收信息、未来问题尚未出现时，如何保留可用的关联，并正确更新局部信息，同时减少对其他关联的破坏。

目标不是单纯提高某项榜单分数，也不是通过增加历史缓存复现完整注意力。应建立“具体失败—机制解释—算法干预—等预算验证—实际价值”的证据链。

当前建议如下：

| 候选方向 | 对应问题 | 当前定位 |
|-|-|-|
| A：保护少量读取地址的约束写入 | 新写入影响其他仍需使用的关联 | 低成本机制筛选；邻近研究较多，新颖性须继续审计 |
| B：固定总字节预算的干扰分流 | 多关联竞争，固定分配不能适应信息负载 | 优先主线候选；先验证静态分区与干扰路由 |
| C：保留修订依赖的历史块重组 | 检索旧证据时跳过了必要的后续纠正 | 面向更新一致性的候选；存储和依赖闭包风险较高 |
| 早期混合方案：压缩记忆＋有限精确 KV＋路由 | 压缩状态难以精确访问部分历史证据 | 作为对照与可选组件，不能仅凭组合认定为新算法 |

本文使用三种证据标签：

- **已有实证**：原论文在其特定模型、数据和实验条件下报告的结果。
- **研究假设**：本文提出的候选机制及其预期作用，需要实验验证。
- **验收目标**：用于决定是否继续投入的暂定门槛，不是已经实现的效果或可靠的提升预测。

8 张 H100 足以支持机制诊断、340M 规模系统消融、胜出方案的 1.3B 扩展与成熟模型适配。它不意味着应该同时对全部路线进行昂贵预训练。

## 2. KDA 的基本原理与仍然存在的限制

### 2.1 从“保存所有历史”到“持续更新一个状态”

完整因果注意力保存历史 token 的 K/V，当前 query 可以对历史位置重新计算相关性。KDA 则把信息写入一个固定形状的状态矩阵。可以把它理解为持续修改的一张关联表，但这张表的行列是向量方向，并不是天然独立的实体或事实记录。

采用状态形状 S∈R^(d_k×d_v)，KDA 的核心递推可以写为：

$$\bar S_t=\operatorname{Diag}(\alpha_t)S_{t-1},\qquad S_t=(I-\beta_t k_tk_t^\top)\bar S_t+\beta_t k_tv_t^\top,\qquad o_t=S_t^\top q_t.$$

等价的纠错表达为 S_t=\bar S_t+β_t k_t(v_t−\bar S_t^T k_t)^T。其含义是：先按通道衰减旧状态，再检查当前 key 对应的已有预测，把残差写回，最后用 query 读取。

KDA 的重要进步是通道级遗忘以及可高效实现的 delta 更新。Kimi Linear 采用 KDA 与 MLA 的混合架构；Kimi K3 同样使用混合注意力，因此不能把整个模型的长上下文表现直接归功于纯 KDA。[Kimi Linear](https://arxiv.org/abs/2510.26692)、[Kimi K3](https://arxiv.org/abs/2607.24653)

### 2.2 已解决与未解决的问题

| 问题 | KDA 提供的能力 | 尚未获得的保证 |
|-|-|-|
| 历史缓存随长度增长 | 递归层保持固定大小状态 | 混合架构的其他注意力层仍可能保存增长的 KV |
| 新值与旧值简单叠加 | delta 残差提供纠错写入 | 不保证自然语言中的“同一事实”一定映射到同一地址 |
| 所有记忆以相同速度衰减 | 不同通道可选择不同遗忘强度 | 不保证重要事实不会被衰减或后续写入影响 |
| 精确历史访问 | query 可以选择性读取当前状态 | 无法重新访问已经丢失的原始历史表示 |
| 局部更新 | 可修改共享状态中的特定方向 | 不保证其他关联完全不变，也不保证未来改写 query 的读出保持 |

因此，KDA 已有选择性读取，问题不是“它完全不能根据 query 取信息”。真正的差别是：query 只能访问当前压缩状态，不能任意回到历史位置重新构造证据。

### 2.3 与 RNN、LSTM 和 Transformer 的关系

RNN/LSTM 的类比有助于理解“递推状态＋遗忘与写入”，但不宜作为严密的技术发展顺序。线性注意力使用矩阵关联记忆；delta 更新又可以从在线回归或 fast-weight 学习理解。

进一步借鉴 Transformer，值得研究的是更细致的内容寻址、查询条件化读取和证据选择，而不是简单把 softmax 加到状态外面。只要记忆预算有限，就不能保证无损保存任意数量的独立随机事实；新算法应证明在特定负载下更有效地利用容量，并明确失效边界。

## 3. 与本研究有关的技术发展脉络

以下是与当前问题有关的代表性路径，不是对所有高效注意力、状态空间模型和 KV 压缩工作的穷尽列表。时间按论文首次公开或主要发展阶段区分，论文修订日期不等于方法首次提出日期。

| 阶段 | 代表工作 | 对当前研究的启发 |
|-|-|-|
| 2020：递归线性注意力 | [Transformers are RNNs](https://arxiv.org/abs/2006.16236) | 借助矩阵乘法结合律，用递归状态处理历史 |
| 2023：并行、递归和分块计算 | [RetNet](https://arxiv.org/abs/2307.08621) | 将训练并行与递归推理结合，说明“递推”不必等于逐 token 慢速训练 |
| 2023–2024：选择性遗忘与硬件实现 | [GLA](https://arxiv.org/abs/2312.06635) | 数据依赖门控与 I/O 感知实现共同决定可用性 |
| 2024：delta 纠错与分块并行 | [Parallelizing Linear Transformers with the Delta Rule](https://arxiv.org/abs/2406.06484) | 纠错写入增强关联记忆，训练内核是算法的一部分 |
| 2024–2025：遗忘与纠错结合 | [Gated Delta Networks](https://arxiv.org/abs/2412.06464) | 同时控制状态保持与残差写入 |
| 2025：通道遗忘和混合架构 | [Kimi Linear / KDA](https://arxiv.org/abs/2510.26692) | 更细粒度状态管理与大模型中的混合部署 |
| 2025–2026：曲率、不确定性与独立擦写 | PKDA、KalmaNet/KDN、GDN2、EDA | 更新方向、擦除地址与写入强度可以进一步解耦 |
| 2026：稀疏寻址与查询相关历史读取 | SDM、GSA2、QED、HLA 等 | 从“怎么写状态”扩展到“怎样分配和访问历史” |

由此可以看到，发展方向不是单一的 RNN→LSTM→Transformer 替代链，而是记忆表达、写入规则、访问方式和硬件执行四条路径共同推进。

## 4. 核心问题、实际意义与早期混合方案

### 4.1 问题应当拆分诊断

| 失败类型 | 具体表现 | 如何区分 |
|-|-|-|
| 写入干扰 | 写入 B 后，原先能回答的 A 变差 | 控制后续写入方向，检查其他关联的读出变化 |
| 衰减损失 | 没有强竞争时，重要关联仍逐渐变弱 | 固定活跃事实数，单独改变距离和遗忘行为 |
| 容量饱和 | 有用关联增多后整体召回下降 | 固定总字节与长度，扫描事实数量和信息熵 |
| 访问失败 | 信息仍可被诊断性探针读取，但正常 query 失败 | oracle 读取仅作上限诊断，与实际读取分开 |
| 修订不一致 | 回答旧值，或引用旧证据跳过新纠正 | 程序生成当前/历史真值与更新关系 |
| 推理失败 | 证据正确但结论错误 | 给定正确证据后测试读者或推理模块 |

近期因果分析在 GLA/GDN 中发现关联负载、写入重叠与可编辑性之间的联系，但也发现不同架构的非目标受损行为不同。这支持研究共享记忆竞争，不能替代在 KDA 上的复现实验。[How Linear Attention Remembers](https://arxiv.org/abs/2609.33093)

### 4.2 具有实际价值的场景

- 长期运行的助手：多个项目、人员、约束和偏好交错进入，后续问题尚未确定。
- 工具型 Agent：复用先前工具观察，避免重复读取，同时正确处理环境变化。
- 代码与配置排障：保留错误证据、修复尝试及生效配置，减少相似模块间的混淆。
- 多文档与多阶段任务：整合跨段证据、更新结论，并回答历史时点的问题。

实际验证应关注完成率、修复测试、重复工具调用、旧值误答和任务总成本。检索分数提升只有在能转化为这些结果时，才支持部署价值。

### 4.3 “压缩记忆＋少量精确 KV”到底提供什么

早期讨论的混合方案包括：压缩状态保存广泛历史，少量精确 K/V 保留局部或选择的重要表示，查询路由决定访问哪些内容，必要时再处理更新关系。

保留 256 个精确 K/V 的作用，是让其中一部分表示避免被共同压进单一状态。它可能为精确复制或关键证据提供更直接的路径；但 256 是预算例子，不是理论最佳值，也不能保证未来真正需要的信息都被选中。

“精确 KV”指保存的神经网络 K/V 表示，不等于保存了独立、完整、无上下文依赖的语义事实。即使保存所有历史 KV，模型仍可能因定位、竞争、位置处理、更新理解或推理失败而答错。

HOLA 已研究有限 KV 与 delta 记忆的结合，因此“加少量精确缓存”本身不能作为新颖性依据。[HOLA](https://arxiv.org/abs/2607.02303)

### 4.4 成本是否与线性注意力目标冲突

单头、单请求，元素占 b 字节时，持久存储的简化量级为：

- 纯 KDA：b·d_k·d_v。
- 增加固定 W 个 K/V：再增加 b·W·(d_k+d_v)，还需计算路由等辅助信息。
- 完整历史 K/V：b·T·(d_k+d_v)。

若 d_k=d_v=128、BF16，纯状态为 32 KiB；256 个 K/V 为 128 KiB；32,768 个 K/V 为 16 MiB。这只是单头算例，未包括模型权重、卷积状态、其他层和训练激活。

固定 W 的额外读取在序列长度意义下仍可保持每步常数、总计算线性，但常数、带宽和批量服务显存都会增加。若保留所有历史块并扫描它们，则不能继续宣称总状态和每步访问成本都固定。

正确评价方式是质量与实际资源的共同曲线，并加入同字节扩大状态、CPU 原文记录、检索系统和重新调用工具等对照。有限 KV 是可选补救路径，不是解决共享状态干扰的充分条件。

### 4.5 为什么版本管理不是唯一主问题

新旧值识别同时受到语义、来源、有效时间和模型推理影响，不是 KDA 特有问题。版本场景可作为选择性维护的严格测试条件，但不宜把整个研究收缩成一个外部版本表系统。

需要区分：当前状态纠正、历史时点问答、必要修订纳入、精确记录删除、模型参数遗忘。这几项性质并不等价。候选算法必须明确自己证明了哪一项。

## 6. 路线 A：限制非目标关联受损的 KDA 写入

本路线研究的是一个尚未验证的算法候选：**在修正当前关联时，显式限制少量历史读取地址受到的干扰**。目标是在较小额外状态下提高有效记忆容量，不是让有限状态保存无限历史，也不是增加一组精确 KV。保护地址只是向量，不能独立还原原文证据。

### 6.1 所针对的问题

KDA 的共享矩阵可以容纳多条关联，但不同内容的写入方向可能重叠。修正当前 key 对应的内容时，其他 query 的读出也可能改变。关键问题不是单纯“经过很久”，而是不断有相似内容竞争同一组状态方向。已有 GLA/GDN 因果实验支持这种解释，但尚不能直接把该实验的数值推广到 KDA。[How Linear Attention Remembers](https://arxiv.org/html/2609.33093)

本路线的待验证假设是：如果少量历史地址覆盖了后续任务常用的信息，可以让新写入绕开这些地址，以较低成本降低非目标关联的损坏。它不能保护尚未识别、已经丢失或超过容量的所有信息。

### 6.2 具体更新规则

以下采用状态 $S\in\mathbb R^{d_k\times d_v}$、读出 $S^\top q$ 的记号。先执行 KDA 衰减，计算当前回归误差：

$$\bar S_t=D_{\alpha_t}S_{t-1},\qquad e_t=v_t-\bar S_t^\top k_t.$$

普通 KDA 写入为 $\Delta S_t=\beta_t k_te_t^\top$。候选算法维护 $r\ll d_k$ 个保护地址，组成 $U_t=[a_1,\ldots,a_r]$，求解：

$$\Delta S_t=\arg\min_\Delta\frac12\|e_t-\Delta^\top k_t\|_2^2+\frac1{2\eta_t}\|\Delta\|_F^2+\frac{\lambda_t}{2}\|U_t^\top\Delta\|_F^2.$$

三项分别要求拟合新关联、限制更新幅度、限制保护地址的读出变化。$\eta_t>0$、$\lambda_t\geq0$，其参数化及取值范围均待验证。该二次目标存在唯一解：

$$u_t=(I+\eta_t\lambda_tU_tU_t^\top)^{-1}k_t,\quad \gamma_t=\frac{\eta_t}{1+\eta_t k_t^\top u_t},\quad S_t=\bar S_t+\gamma_tu_te_t^\top.$$

通过 Woodbury 恒等式，令 $\rho=\eta_t\lambda_t$，可避免求 $d_k\times d_k$ 的逆：

$$u_t=k_t-\rho U_t(I+\rho U_t^\top U_t)^{-1}U_t^\top k_t.$$

当没有保护地址、$\|k_t\|_2=1$ 时，取 $\eta_t=\beta_t/(1-\beta_t)$ 可以恢复普通 delta 写入。实现需避免 $\beta_t$ 过于接近 1，使用有界参数和 FP32 正定小矩阵求解，并检查长序列状态范数与梯度。这不构成整个递归系统在 Euclidean 范数下非扩张的证明。

对于 $\lambda_t>0$，由最优目标不大于零更新的目标，可得局部边界：

$$\|U_t^\top\Delta S_t\|_F\leq\|e_t\|_2/\sqrt{\lambda_t}.$$

该边界只约束本次写入在保护地址上的扰动，不保证最终答案正确或所有历史关联保持。算法效果、有效强度及实际代价全部待实验验证。

### 6.3 保护地址如何选择、何时释放

第一阶段可用已知关联的 key 做机制诊断；第二阶段需要学习能够预测未来读取需求的地址。候选来源包括已发生的 query、历史内容产生的读取代理向量、因果聚合的少量代表。推理时不得使用未来问题。Oracle 地址只能用于测量算法上限，不能混入实际方案结果。

必须区分 key 与 query：写入回归在 key 上拟合，实际回答在 query 上读取。保护旧 key 并不保证改写、别名或不同措辞的未来 query 得到保护。实验应包含这种读取变化，不能仅测试完全重复的地址。

新内容明确覆盖同一对象的旧值时，应释放或降低相应旧地址的保护；否则算法可能固化错误或旧版本。反之，相似对象不能被误判成更新同一事实。“最新出现”也不能自动视为“当前有效”。释放策略需要学习或可信结构化信号，其识别错误属于待验证风险。保护银行中的地址不能假定为独立、精确的事实槽。

### 6.4 遗忘门与并行实现的边界

上述约束参照的是衰减后状态 $\bar S_t$。因此，$D_{\alpha_t}$ 已经造成的损失不会被恢复。若把保护目标改为衰减前读出，必须联合求解完整状态修正，额外工作也需计入。第一阶段应固定或控制衰减，独立观察写入干扰；不能把局部保护称为整体防遗忘。

建议在块边界维护地址银行、块内固定 $U$。条件于该银行，token 更新仍可写为非对称 rank-one affine recurrence：

$$S_t=(I-\gamma_tu_tk_t^\top)D_{\alpha_t}S_{t-1}+\gamma_tu_tv_t^\top.$$

这为 chunk 并行提供可能，但不代表现有 KDA 内核可直接复用。需重新验证前向、反向及边界同步。如果地址选择依赖当前主状态误差，并逐 token 替换银行，额外串行依赖可能吞掉性能收益。块内固定银行也可能错过刚写入的重要内容，需作为消融。

梯度需经过小矩阵求解、地址、key/value、门及主状态。离散 top-k 不可直接微分，须明确采用软聚合、代理梯度或固定选择。若 detach 银行或截断反向，应如实报告，不能称为完整梯度训练。

### 6.5 与已发表工作的重叠

- [PKDA](https://arxiv.org/html/2604.21100) 已用历史 key Gram 的对角近似改变 delta 更新，并将其联系到持续学习的二次保护正则。低秩替代对角预条件本身不足以证明创新。
- [Gated KalmaNet](https://arxiv.org/html/2511.21016) 与 [Kalman Delta Networks](https://arxiv.org/html/2609.07816) 已研究历史统计、协方差及不确定性驱动的递归更新。不能仅把历史感知或 inverse 公式改名。
- [QED](https://arxiv.org/html/2608.13668) 用当前 query 提供与 key 正交的附加擦除分量，写入方向仍为当前 key；本候选改变写入方向，约束多个历史读取受到的副作用。目标有区别，但宽泛的 query 感知、正交更新主张已有先例。
- [Lattice](https://arxiv.org/html/2504.05646v2) 将更新投影到当前记忆槽向量的正交方向；[EDA](https://arxiv.org/html/2606.26560) 解耦擦除与写入地址。两者均需列为邻近工作。

可能的贡献是保护地址的选择与释放、局部扰动分析及高效块实现的组合；新颖性仍待进一步审计，当前不能认定形成了新的 Transformer 架构。

### 6.6 预期场景与失败条件

预期获益场景均待验证：活跃关联数量中等，内容相似但地址仍有可分离方向，后续任务反复访问部分早期约束、工具观察或对象关系。多服务排障与跨项目工具结果复用可用于验证实际价值。

硬投影极限揭示根本边界：若当前 key 位于保护地址张成的空间中，无法同时修改它并保持全部保护读出不变；近共线时强行拟合可能放大更新。正则化只能折中，不能创造新秩。容量饱和、保护对象选择错误、频繁更新及原本近正交的 key 都可能没有收益或出现下降。

### 6.7 实验、资源与停止条件

先做受控矩阵实验：改变关联数、key 重叠、重复写入、更新频率，并分别控制长度和衰减。报告目标拟合、非目标受损、累计召回、范数与梯度，多随机种子验证。再做小模型的多事实改写查询，最后进入工具排障，以正确根因、修复测试和重复工具调用衡量实际任务。

诊断数据需要同时包含“必须保护”和“必须改写”的情况。例如多个服务共享相似配置名，只有一个服务变更；查询既要求当前配置，也要求找回另一个服务的早期测试条件。对照组应保持事实数量、长度与对象分布一致，避免把较少干扰误认为算法收益。实际任务还应与短窗口加摘要、重新调用工具或外部检索比较。如果便宜的重读已经达到同样效果，不能仅凭神经记忆更复杂就认定具有部署价值。

必须与 KDA、PKDA、QED、同字节扩大状态及随机/Oracle 地址对照。最终比较需包含吞吐、每请求显存、训练代价，而非只比较 FLOPs。以 $d_k=d_v=128,r=8$ 为例，BF16 主状态为 32 KiB；BF16 地址、FP32 小 Gram 与优先级约增加 2.28 KiB/头，即约 7.1%，不含训练激活及其他工作空间。每 token 新增约 $O(d_kr+r^2)$，边界分解约 $O(d_kr^2+r^3)$，实际速度待 H100 测量。

建议用现有 8 张 H100 中的少量卡先验证机制，其余并行跑基线与种子。以下验收线均是建议、待验证：同资源减少非目标受损且不伤害覆盖更新；相对 PKDA/QED 形成质量—成本优势；学习地址接近诊断上限；块实现没有严重吞吐损失。若收益被扩大 KDA 状态或 QED 达到，或只在 Oracle 地址下有效，应停止扩大预训练投入，重新定位问题。

## 7. 路线 B：固定总记忆预算，用干扰信号调度多个 KDA bank

### 7.1 要解决的问题与研究边界

这条路线研究的是：在同一有限记忆中维护很多关联时，能否减少后续写入对无关关联的破坏。它不以增加 bank 数量证明容量提高，也不假设一个 bank 天然对应一个项目、一条事实或一个独立语义空间。KDA 本身已经有多个头；仅把状态矩阵改称多个 bank，不构成充分的创新。

SDM 已用稀疏读写访问大状态，但其主要对照固定 FLOPs，而状态容量大幅增加；GSA2 已通过 key—slot 与 slot—value 两阶段纠错改善关联记忆；NHA 已将长期 slot 与近期精确表示联合读取。这里仍值得检验的缺口是：**整套历史状态总字节数相同时，利用实际干扰信号分流写入和重新分配容量，能否优于静态组织。**这属于待验证假设，不能从上述论文直接推出。[SDM](https://arxiv.org/html/2607.07386)、[GSA2](https://arxiv.org/html/2610.02816)、[NHA](https://arxiv.org/html/2510.07019)

### 7.2 最小可实现结构：静态 bank 先行

每层每头预分配 $M$ 个 bank，$S_b\in\mathbb R^{r\times d_v}$。以下 $k_t,q_t\in\mathbb R^r$ 是投影到 bank 地址维度后的向量，$D_{t,b}\in\mathbb R^{r\times r}$。另设地址原型 $c_b$、有限探针和使用统计。所有空闲 bank 也计入预算；计数器、父子关系、局部卷积缓存及可选精确缓存都不能放在预算外。

若每个数占 $s$ 字节，一个保守的约束为：

$$s[Mrd_v+Md_r+Mp(r+d_v)]+B_{\rm metadata}+B_{\rm local}\le B_{\rm total}.$$

这里固定的是机制整套每请求历史状态。模型参数、训练工作区、服务临时张量与整机显存还需单独记录；“状态等容量”不自动等于“总显存相同”。第一版不增加额外精确 K/V，便于判断组织记忆本身的价值。

每个 token 用当前隐表示和已存在的地址原型选择少数 bank 写入。对选中的 bank，采用 KDA 式更新：

$$\bar S_b=D_{t,b}S_b,\qquad S_b'=\bar S_b+\beta_{t,b}k_t(v_t-\bar S_b^\top k_t)^\top.$$

未选中的 bank 保持不变。查询选择少数 bank 并读取：

$$o_t=\sum_{b\in\mathcal R_t}\rho_{t,b}S_b^\top q_t.$$

这种选择性更新能避免无关 token 对所有 bank 都施加衰减，但也可能遗漏真正必要的修订。地址绑定和读取必须学习；同一事实的不同说法未必落到同一 bank，多个事实也仍可能混在同一 bank。

### 7.3 怎样测量干扰，怎样安排调度

每个 bank 保留固定数量的过去键方向作为探针。对候选更新，比较这些方向更新前后的读取变化：

$$I_b(t)=\sum_{\ell\in\mathcal P_b^{\rm unrelated}}\|u_\ell^\top(S_b'-S_b)\|_2^2.$$

如果当前内容正在合法修改某关联，该关联对应的变化不应被惩罚。因此需要一个内部关系预测器，区分可能属于同一关联的探针和无关探针。该预测也可能出错；干扰分数只是诊断信号，不是“事实被破坏”的完美检测器。尤其不能把 delta 残差大直接等同于干扰：新信息、正确版本更新、难预测内容都会产生大残差。

第一版先固定 bank 数量与组织，只比较地址路由、加入干扰惩罚的路由，以及随机/hash 路由。后续再在块边界安排容量调度：块内使用固定组织，块完成后才决定未来的分流、合并和淘汰。可使用已完成块的统计，不能回头用块后半段决定前半段输出。训练中未来目标产生梯度是正常监督，前向写入不能看到未来问题。

### 7.4 分流、合并、淘汰与关系释放

最安全的 split 是“分流以后写入”：高干扰 bank 保留旧状态，从预分配空闲槽中启用一个 bank，将后续某类键簇写到新槽。过渡期读取可联合访问原 bank 与新 bank。**已压缩进一个矩阵的旧事实，不能自动无损拆成两个语义集合。**如果增加历史拆分，只能使用投影或学习重编码，并单独测量拆分前后读取失真。

没有空槽时，优先寻找探针读取行为相近、合并损伤低的 bank。第一版可用低成本的加权状态合并，例如 $S_\star=\gamma_aS_a+\gamma_bS_b$，以有限探针上的读取误差选择系数和合并对象。它通常不能保留两套不同的查询权重、门控历史与关联边界，不能称为精确合并。失真过大时才淘汰低使用、低保护优先级的 bank；被淘汰内容的召回下降必须报告。

父子/重定向关系同样采用固定容量表。合并、淘汰后更新地址与关系引用，迁移或删除有限探针，清除悬空指针；过渡关系只有在规定的探针一致性检查通过后才能释放。检查通过也不保证未知未来查询正确。若方法依赖不断增长的关系链、探针或备份，便违反固定总容量的研究设定。

### 7.5 预期、成本、验证与停止条件

最可能受益的是多主题交错、多实体状态维护、很多工具结果竞争共享记忆的情况。主要失败区间包括：事实数超过容量、地址混淆、查询需要遍历全部事实、合并/淘汰损失，以及路由偏爱高频查询而丢失未来才重要的内容。

共享投影、每步读 $u$ 个和写 $w$ 个 bank 时，核心读写约为 $O((u+w)rd_v)$，路由约为 $O(Md_r)$；探针评估还增加固定开销。固定 bank 和探针数量时，每步成本不随历史长度增长。但硬路由、调度和不规则访存可能使实际训练慢于现有 KDA，不能把理论操作数当吞吐结论。

任务应独立改变事实数、距离、键相似度、更新次数和查询分布。先用随机键值及自然语言改写，之后加入配置、项目、工单与工具日志。指标包括目标更新成功率、未修改事实损伤率、旧值误答率、不同事实负载下的召回，以及相同总字节数下的有效容量。需要比较普通多头 KDA、扩大状态的 KDA、静态 bank、SDM/GSA2 适配对照；全部使用同等训练数据和调参机会。

要区分“路由猜中了题型”和“记忆组织确实更好”，未来问题应在写入完成后随机抽取，并加入低频实体与训练时未见的改写。探针也会偏向采样过的键，因此同时报告探针覆盖内、覆盖外事实的表现，并比较随机探针、仅最近探针、去掉干扰项三种控制。可以用已知关联归属的理想路由估计可达上限，但必须与实际路由单列；不能把理想分组结果当作架构已经学会语义独立存储。

容量测试需列出每一类状态的真实张量形状、精度和字节数，并固定共同的最大预算。拆分、合并发生前后对同一组保留事实做配对查询，才能定位失真。若新的输入只是正确修改了目标事实，应奖励目标改变，并检查其他事实是否保持；若只记录总状态变化大小，会把有益修改与破坏混为一谈。训练种子或配对区间用于判断收益稳定性，不能以某一次最好结果替代整体报告。

建议预先规定项目门槛，例如高干扰区准确率至少增加 5 个百分点、无关事实损伤相对减少 30%，同时低负载准确率不降低超过 1 个百分点。这些数值是**可修改的假设目标，不是论文已有结果或行业标准**。若等容量后收益消失、只能靠增加 bank 总字节数提升、分流收益被合并损伤抵消，或实际路由不优于简单 hash，应停止堆叠组件，转向机制诊断。

## 8. 路线 C：查询重组历史时，保留必要更新依赖

### 8.1 问题与已有工作的距离

这条路线研究一个更具体的问题：为了找回远处证据而跳过历史块时，怎样避免同时跳过后来使这条证据失效的更新。旧值容易匹配查询、新修订表达不同，便可能出现“旧内容记得更牢，答案反而更错”。这是可构造的算法风险，不是已经证实 HLA 在所有实际场景都存在同样失败。

HLA 用查询门控历史块的完整仿射转移；HLA-WM 在视频世界模型中根据几何相关性选择块并重组，允许远处记忆绕过无关中间转移。因此，普通的 query-dependent chunk routing 已有直接先例。候选新点应是**让稀疏读取保持必要修订关系，并量化这种约束的收益与代价**。[HLA](https://arxiv.org/html/2610.05842)、[HLA-WM](https://arxiv.org/html/2610.05739)

### 8.2 固定槽位、因果摘要与依赖闭包

预分配最多 $J$ 个历史块槽，存储 $F_j(S)=A_jS+B_j$、固定数量的路由代表和内部依赖摘要。KDA 的更新也是仿射形式，可构造块转移。完整块只在完成后供未来查询使用；当前块只能提供当前 token 的因果前缀。

查询先选初始证据集合 $\mathcal R_0(q)$。新块 $j$ 到来时，利用已存在块 $i<j$ 的潜在写入方向、关联地址和纠错摘要，预测 $d_{ij}$：后来的 $j$ 是否修订、撤销或改变 $i$ 提供的关联。这是内部可训练的依赖图，不使用外置实体—版本数据库替模型完成绑定。

可把 $\|E_jB_i\|_F$ 作为特征之一，其中 $E_j$ 表示纠错/擦除方向。它只能提示重叠，不能证明语义更新。若直接用完整 $A_j-I$，普通衰减也会产生依赖，容易使图接近全连接；还需区分“无关干扰”和“必要纠正”。

读取集合加入选中节点的必要后继：

$$\mathcal R(q)=\operatorname{Closure}_{d_{ij}}(\mathcal R_0(q)).$$

软训练可采用顺序传播 $\tilde w_j=\max(w_j,\max_{i<j}\tilde w_i d_{ij})$；推理可用阈值边和硬闭包。最终按时间顺序组合选中转移。依赖只在后续块到达时建立，不使用未来块；正确性仍受依赖识别误差限制。

历史时点查询只闭合到指定时点。第一版宜使用明确的序列边界；“事件生效时间”和“消息到达时间”不同的情形需要另设任务，不能把“最后出现的值”自动当成最新有效值。

### 8.3 满容量合并与超读取预算回退

槽满时可合并相邻历史区间：

$$A=A_{j+1}A_j,\qquad B=A_{j+1}B_j+B_{j+1}.$$

这对已经计算的仿射系数保留完整转移，却失去区间内部的选择性。依赖摘要保守取并集会增加无谓读取。若历史查询的截止时点落在已合并区间内部，而没有预算内的细粒度摘要，就不能精确切开；应明确可支持的历史粒度，不能暗中保存无限备份。

闭包超过通常的读取数预算时，应回退读取全部固定 $J$ 个槽，或者本次不采用稀疏读取。不能又截掉纠正块，否则约束失去意义。该设计使最坏容量与计算有上界，但回退频繁时不再具有稀疏读取价值。

### 8.4 为什么不能叫精确遗忘

原轨迹中的 $A_j,B_j$ 来自当时的隐表示。删除或改变更早内容，也可能改变后续隐表示、卷积状态和其他层的表示。重组旧摘要只改变已有转移的使用，并不保证等价于“原记录从未出现”。Exact Record Omission 专门区分了停止回答被删内容与恢复 never-stored 状态，并给出运输校正与回放的条件和审计。这里的主张应限制为行为与修订一致性；如果要宣称精确删除，需要受影响后缀回放或更强的证明。[Exact Record Omission](https://arxiv.org/html/2609.06872)

### 8.5 成本、预期、验证与停止条件

精确摘要、路由代表与稠密依赖图的状态量约为 $O(J(d_k^2+d_kd_v+Pd_r)+J^2)$，还需当前块缓冲。查询打分约 $O(JPd_r)$、朴素闭包约 $O(J^2)$；用反向 query transport 读取 $m$ 个块约为 $O(m(d_k^2+d_kd_v))$。相邻精确合并包含矩阵乘法，约 $O(d_k^3+d_k^2d_v)$，可以在块结束时摊销。低秩摘要能降成本，却引入截断误差，应作为后续变体。

固定 $J$ 不等于与纯 KDA 等容量。同维度下，多槽双矩阵显然更贵；必须让对照也拥有相同总字节数，或在共同预算内调整维度。预计收益集中于跨块修订、撤销和依赖链；失败可能来自别名绑定错误、依赖遗漏、误报导致闭包膨胀、老区间合并，以及容量不足。

先做理想依赖图实验：使用无歧义键、简单 delta 更新和已知正确修订关系，验证闭包确实避免跳过纠正。再训练关系预测器，加入旧证据易检索、新更新难检索、跨块二次修订、历史查询和无关事实保护任务。报告必要更新召回率、旧值误答率、当前值与历史值准确率、闭包大小、回退率、合并前后失真。

对照应包括普通 HLA 路由、按相同实际读取块数的朴素 top-k、补充最近块、保留全部后续转移和读取全部 $J$ 槽。建议门槛为旧值误答相对减少 50%，平均读取不超过 J/4、回退全读不超过 10%，同时当前事实召回与历史查询下降不超过 1 个百分点；阈值属于待检验项目目标。若理想图也无收益，说明问题不在更新遗漏；若学习图接近全连接、频繁回退，或加入相同数量普通块即可取得同样收益，应停止宣称依赖约束形成独立优势。

一个关键配对样例是：早块记录“项目 A 的账号为 7319”，后块记录“此前账号已停用，启用 9173”，中间插入无关项目。当前值查询应得到 9173；早期时点查询应得到 7319；无关项目查询不应受影响。负例应包含“项目 B 改为 9173”和“仅讨论是否更换账号”，防止关系预测器把所有相似数字或变更措辞都当作修订。还需将新更新的表达改写、位置移动、关联名称替换，检验依赖识别能否迁移。

第一阶段可用生成器提供正确依赖作为监督，第二阶段只让模型读取前缀输入；生成器的实体标识不能直接留在运行时状态中替代模型的绑定能力。各对照也应获得相同训练样例，避免把额外的修订数据效果误归因于架构。最终需要同时展示三件事：纠正被检索到了、当前答案变正确了、历史答案与其他事实仍可正确读取。只证明“不再回答旧值”，不能排除模型把整个关联忘掉。

两条路线可先各自验证，不宜立即合成一个复杂架构。B 首先检验有限状态的组织是否减少干扰；C 首先检验跳过更新是否构成独立失败机制。只有这些核心证据成立，才值得研究二者结合。

## 9. 实验设计：证明增益来自算法，并确定适用边界

本方案仍是待验证的架构假设。实验需要同时回答三个问题：在相同资源下是否更准；更准的原因是否来自保护写入、干扰分流或必要更新闭包，而非增加容量或额外训练；这些收益是否能转化为实际业务中的成本优势。不能把其他论文在 GLA 或 GDN 上的结果直接当作 KDA 的证据，也不能将分块与精确缓存各自的增益相加。

### 9.1 三层验证与数据划分

**机制层**先用约 100M 参数的模型和可控任务验证保存、修改与读取。独立改变事实数量、问题与证据的距离、无关 token 数、相似键数量、更新次数和更新链长度，避免只增加序列长度。加入随机编号和不可由常识补全的值，检验精确保存；问题只在历史结束后出现，检验未知未来问题下的保留能力。主要对照必须包括自行复现的纯 KDA。

**语言层**用 340M 模型、15B tokens 比较完整架构和关键消融，随后只把胜出方案升级到 1.3B、100B tokens。固定 tokenizer、骨干、数据顺序和训练窗口，分别进行同训练 tokens 与同训练计算预算比较。前者检验架构效果，后者检验资源效率。记录真实 FLOPs 和 GPU 时间；相同参数与 tokens 不自动意味着相同成本。

**场景层**在成熟模型适配后验证长对话、多文档和代码检索；最后再测试交互式 Agent。小模型复杂问答分数接近底线时，先确认骨干具备短上下文解题能力，避免把推理能力不足误判为记忆失败。适配与从零训练是两条证据链，不可混作同一实验。

合成训练、验证与测试使用分离的随机种子、实体集合和生成模板。除随机划分外，额外保留未见过的表达方式、事实密度、修改操作和长度组合。自然语料按文档划分并去重；公开测试题、答案及其改写不能进入训练。合成课程可以从短历史逐步延长，混入自然文本，但课程样本须独立生成，公开评测保持 held-out。

质量比较前须验证实现正确性：逐 token 参考实现、分块训练和增量解码在允许的数值误差内一致；一个问题不能读取尚未完成的未来块。测试跨块更新、缓存淘汰、批处理重排与状态回滚，防止因训练看到了未来证据而获得虚假的提升。若训练采用连续路由、推理采用离散选择，应单独测量这种转换造成的质量差异。

### 9.2 强基线与机制消融

基线不只是一种固定配置，应比较各方案的质量—资源曲线。

| 基线或对照 | 需要排除的解释 |
|-|-|
| 纯 KDA 与扩大状态的 KDA | 新方案是否只因使用更多容量而更准 |
| 同缓存字节预算的 KDA 配置 | 将同样的显存花在原有机制上，能否达到相同效果 |
| PKDA、GDN2、GDN2＋QED | 增益能否超过预条件、解耦擦写与问题相关擦除等改进 |
| 相同记忆银行，静态／哈希／最近／随机路由 | 路由是否真正学会根据问题选历史，而非仅扩大记忆 |
| 同容量精确 KV，最近／随机／写入强度选择 | 缓存选择是否优于简单策略 |
| HLA 在相同历史缓存预算下的配置 | 分块读取能否超过已有问题驱动分块机制 |
| KDA＋MLA，改变全注意力层比例 | 增加路由是否优于把预算花在更多全注意力层上 |
| 完整注意力、滑窗注意力及外部记录检索 | 与强完整记忆路径、局部路径和原文检索相比的实际价值 |

PKDA、GDN2 与 QED 的方法依据分别来自[预条件 KDA](https://arxiv.org/abs/2604.21100)、[GDN2](https://arxiv.org/abs/2605.22791)和[问题导向擦除](https://arxiv.org/abs/2608.13668)。比较时统一训练配方并给各方法合理的超参数调优预算，不能直接引用跨论文分数作为胜负证据。[Kimi Linear](https://arxiv.org/abs/2510.26692)的 KDA＋MLA 是重要工程基线；[HLA](https://arxiv.org/html/2610.05842)保留历史分块，原始配置的缓存随历史增长，同预算版本须说明如何合并或淘汰，不能冒充原始配置。

消融按路线分别设置：A 去掉保护、替换保护地址或释放策略；B 去掉干扰项、固定调度或替换路由；C 去掉依赖闭包、补最近块或全读。若包含早期混合方案，再测试去掉精确 KV、去掉分块及版本有效性组件；没有这些组件的路线不必人为增加它们。随机与最近路由保持实际读出的块数相同；正确证据的 oracle 路由只作诊断上限。删除组件的消融解释组件作用，重新分配节约容量的实验解释资源效率，两者分别报告。

同预算比较采用真实字节而非标量数，不能把单精度状态与半精度 KV 当作同样大小。参数、训练 tokens、计算、显存和延迟通常无法同时严格匹配，应分别作对照并公开未匹配项。固定容量方案与保存全部历史块的方案分开报告；选择少量块之后的计算便宜，并不意味着寻找这些块也便宜。若扫描所有候选，仍须报告历史增长时的路由开销。

### 9.3 数据集如何使用

| 数据或任务 | 用途与边界 |
|-|-|
| [FineWeb-Edu](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu)、[SlimPajama](https://training-api.cerebras.ai/en/2.1.1/wsc/port/prepare-data/slim_pajama.html) | 一般语言建模训练；独立测试 loss 与短任务回归，不能代替长记忆验证 |
| [MQAR／Zoology](https://arxiv.org/abs/2312.04927)、自建随机 ID | 可控关联召回、容量和干扰诊断；合成训练与测试实例分离 |
| [RULER](https://arxiv.org/abs/2404.06654) | 单针、多事实、变量追踪与聚合，报告全部分项，不能只展示最好的一项 |
| [BABILong](https://arxiv.org/abs/2406.10149) | 分散事实的多跳推理、计数与集合处理，检验检索后能否正确整合 |
| [LongMemEval](https://arxiv.org/abs/2410.10813)、[LoCoMo](https://github.com/snap-research/locomo) | 长对话中的信息抽取、时间关系和跨会话推理；前者特别包含更新与拒答能力 |
| [LongBench v2](https://arxiv.org/abs/2412.15204)、[InfiniteBench](https://arxiv.org/abs/2402.13718) | 成熟模型上的现实长文本迁移，覆盖复杂问答与需要广泛上下文的任务 |
| [RepoQA](https://github.com/evalplus/repoqa)、[RepoBench](https://arxiv.org/abs/2306.03091) | 长代码定位函数与仓库补全；并不等价于修复实际 issue |
| [SWE-bench](https://arxiv.org/abs/2310.06770) | 后期 Agent 修复与执行验证，固定工具和推理预算，避免工具策略掩盖记忆机制 |

版本任务须另建具有程序化答案的事件流：实体、属性、值、有效时间、来源和修改关系由状态机记录，同时生成“当前值”与“过去某时刻的值”。加入别名、同名实体、乱序到达、引用旧值、计划与假设、局部撤销及更新链缺失。首先在可靠元数据条件下验证规则，再测试模型从自然语言提取元数据的误差，不能混淆这两种难度。

[LongMemEval-V2](https://xiaowu0162.github.io/longmemeval-v2/)更贴近工具观察和环境经验：451 个问题，涉及静态状态、动态变化、工作流、陷阱和错误前提。其历史含截图与 accessibility tree，达到数千万 token，适合后期系统验证。原协议以固定 Qwen3.5-9B reader 和 200K-token 证据上限隔离记忆质量。纯文本架构可做明确标注的文本子集，不能与官方多模态分数直接比较；返回原文或截图还需保存出处及外部原始记录，相关存储和访问时间计入成本。

### 9.4 指标、预期与验收门槛

除了问答正确率，记录目标事实更新成功率、原本正确的非目标事实被破坏的比例、当前值与历史值正确率、过期值误答率、证据保留与路由召回，以及拒答条件下的准确率与回答覆盖率。容量定义为：在预先指定的正确率门槛下，能够稳定处理多少独立事实；同时测未知未来问题和未见改写。机制层和 340M 的主要比较至少三个随机种子，按相同题目做配对统计，报告均值、区间及失败案例；大规模筛选若只能跑单种子，应声明证据边界。

**以下是研究预测，不是实验结果：**相对纯 KDA，少量关键事实的远距离检索、主题交错和明确更新最有希望受益；相对同显存扩大 KDA，优势尚不确定；相对 KDA＋MLA，预期增益较小，应优先争取更低成本下接近其质量；全文统计、完整枚举和高密度随机事实可能退化。版本过滤可能降低过期回答，也可能因新证据缺失而降低覆盖率。

可在开发集上预先确定继续投入的门槛，例如：同历史显存预算下，目标任务平均提升至少 3 个百分点且没有明确的一般能力退化；或者同质量下显存减少至少 20%；或者在固定质量及延迟要求下提高有效吞吐。这里的数值仅是项目管理假设，应在正式测试前锁定，不能看完测试结果后调整门槛。

部署测量同时覆盖预填充、解码、单请求与高并发。统计每请求历史字节、峰值显存、TTFT、TPOT、p50／p95 延迟和符合服务要求的吞吐。计入全部层与头的状态、KV、路由索引、版本元数据、转移矩阵和临时空间，声明真实 dtype 与共享 KV 头数。外置 CPU／SSD 记录不算免费资源。

实际价值以同硬件、同任务分布、同输出预算下的“每成功任务成本”衡量：总 GPU 时间或费用除以满足正确性与服务时限的成功请求数；同时报告失败率。不能把更大 batch 的吞吐与基线 batch 1 延迟混比，也不能只用理论 FLOPs 推导服务收益。

## 10. 8 张 H100 80GB 的算力与时间预算

### 10.1 计算口径与单次训练

全参数 dense 语言模型训练可先用 F≈6ND 估算骨干计算，N 是模型参数规模，D 是训练 tokens。新增注意力、路由、teacher 前向、激活重算另计。冻结骨干或 LoRA 不代表只计算可训练参数：骨干前向及部分反向仍存在，适配须重新计时。

以下采用每卡持续有效计算 100～250 TFLOP/s 的**规划假设**，不是实际速度承诺。表中为单次完整训练的骨干估算，未计新增机制和工程损耗；1 GPU 小时表示一张卡工作一小时。

| 训练配置 | 骨干计算 | GPU 小时 | 8 卡理想运行时间 |
|-|-|-|-|
| 340M，15B tokens | 30.6 EFLOP | 34～85 | 约 4.3～10.6 小时 |
| 1.3B，100B tokens | 780 EFLOP | 870～2,170 | 约 4.5～11.3 天 |
| 已有 7B，全参数适配 1B tokens | 42 EFLOP | 47～117 | 约 5.9～14.6 小时 |

[NVIDIA 官方性能说明](https://github.com/NVIDIA/exemplar-performance)给出的 H100 BF16 非稀疏理论峰值为 989 TFLOPS，不能将带稀疏条件的 1,979 TFLOPS 代入普通训练预算。[GDN2 论文](https://arxiv.org/html/2605.22791)报告其 1.3B 混合模型单 H100 训练吞吐约 36.1～38.0K tokens/s，仅作为实现良好的参考，不代表本方案速度。

### 10.2 实测排期与研究总预算

正式排期前，在本机分别测原生 KDA 与新算子的 200～1,000 个稳定 step，包含真实序列长度、优化器、数据装载、checkpoint 和分布式通信。随后按“总 tokens÷8 卡实测集群 tokens/s”预算；如果路由扫描所有历史块、访问不连续或回传难以融合，实际时间可能明显超过表中范围。

| 阶段 | 示例总预算 | 运行规模与继续条件 |
|-|-|-|
| 机制原型 | 50～200 GPU 小时 | 约 100M 模型、多种容量与更新压力、至少三种子；先证明 KDA 上的收益与非目标保护 |
| 340M 筛选 | 500～1,800 GPU 小时 | 核心四配置各三种子，加少量筛选消融与评测；更广预算扫描另计 |
| 规模与场景验证 | 2,000～8,000 GPU 小时 | 少量胜出配置做 1.3B 主实验，或已有 7B 适配；根据结论选择，不能默认覆盖所有组合 |

三个阶段合计约 2,550～10,000 GPU 小时，理想占满 8 卡约 13～52 天。该总量是项目预算示例；扩展种子、增加基线和长窗口课程需重新计算。评测也消耗大量预填充 tokens，应按实际样本和输入长度单列。

### 10.3 工程日历与路线差异

对路线 A，先按约 2～4 周安排更新规则、梯度、保护选择与块实现；路线 B 约 3～6 周安排路由、有限调度和初步高效实现；路线 C 约 4～8 周安排依赖学习、合并与读取。这是基于已有训练框架的工程量预留，不是完成日期承诺，也不是三条都必须完成的计划。逐 token 原型可能比现有融合内核慢很多，不应直接据此外推算法最终成本。

日历时间还包括数据与答案核验、训练／解码算子开发、数值稳定性修复、评测和服务集成。可先按原型 1～2 周、数据与高效算子 2～4 周、筛选与场景验证 3～6 周安排；部分并行，具体取决于人员和实现难度。无需最初完成大型预训练、SFT 与 RL 的全流程：先证明机制与资源边界，再按拟宣称的能力追加训练；声称交互可靠性时，才需要与强基线一致的后训练和 Agent 验证。

## 11. 综合预估、验收门槛与路线选择

### 11.1 能否达标的当前判断

截至本文件整理时，没有新算法的运行结果。因此不能可靠给出“最终提高多少个百分点”或具体成功概率。下表是基于机制和已知边界的定性判断；数字是暂定项目目标，必须在试验前冻结，不能在看过测试结果后重新定义。

| 路线 | 最可能出现的收益 | 当前主要障碍 | 建议验收目标（非实证结果） | 决策 |
|-|-|-|-|-|
| A：约束写入 | 中等负载下减少相似关联受到的写入副作用 | KDA 基线损伤可能已经很低；保护选择错误；覆盖受阻；近邻研究重叠 | 在匹配目标更新成功率时，非目标受损率相对下降至少 30%，且同字节下仍有效 | 先投入短期验证；把握偏低至中等 |
| B：干扰分流 | 多主题交错时提高有限记忆的有效使用量 | 分区损失、路由错误、跨区整合、管理内核 | 在受控任务召回率≥90%的定义下，有效容量达到同预算基线约 1.5 倍；低频与跨区事实不明显恶化 | 优先主线；把握中等 |
| C：修订依赖 | 减少检索旧证据但遗漏纠正的错误 | 更新关系漏检、依赖图过密、块存储开销 | 旧值误答相对下降≥50%，平均读取≤J/4，回退全读≤10%，新值与历史问答下降不超过 1 个百分点 | 条件性方向；真实迁移仍不确定 |

“相对下降30%”表示错误率从例如10%降到7%，不是准确率增加30个百分点。基线错误率接近零时，不应追求这一比例，而应重新判断问题是否值得解决。90%有效容量门槛只用于可控关联任务，不能直接套用到通用自然语言问答。

三条路线都需要在至少一个与目标问题对应的自然语言或工具场景上复现收益。通用语言建模、短上下文能力和跨事实推理作为回归项；不能接受用广泛退化交换单一诊断分数。

### 11.2 推荐的工作顺序

1. 先复现 KDA 自身的失败区域：活跃事实数量、地址相似度、更新频率、距离分别变化。若主要问题是读取而非写入，应相应调整研究路线。
2. A 用固定/Oracle 保护地址验证可行上限；B 用固定区域与简单路由验证同容量分流；C 用已知修订图验证路由反例。此时仅做机制诊断，不宣称可部署算法。
3. 去掉 Oracle 输入，训练因果保护选择、干扰路由或修订预测。判断瓶颈在主更新机制还是辅助识别器。
4. 340M 做单独路线和关键消融。不要先把 A、B、C 全部加入，否则无法解释收益来自何处。
5. 仅把稳定胜出方案扩大到 1.3B 或成熟模型适配，并在实际任务中比较完整成本。
6. A 与 B 的组合仅在两者独立有效后评估交互。有限精确 KV 只在诊断确认需要精确访问时再加入。

### 11.3 停止条件与转向条件

- 同字节扩大 KDA、静态/hash 分区或 QED 已能解释全部收益：停止把该组件作为独立创新。
- 固定/Oracle 地址有效、学习地址长期无效：将问题定位为选择策略，不继续扩大预训练掩盖它。
- 保护旧记忆导致覆盖更新退化：修正释放机制，不能只汇报旧事实召回。
- 动态分区只有更多总状态时才有效：重新定位为容量扩展，不能继续宣称同预算分配优势。
- 修订闭包几乎总是全读：说明依赖结构不支持有用稀疏化，改用固定全读或更简单记录系统。
- 原型有益但高效实现长期不能达到合理吞吐：分别汇报算法证据和工程限制，不宣称可部署优势。
- 外部原文记录、检索或重新调用工具更便宜且更准确：将其作为实际推荐，不因神经机制更复杂而排除。

## 12. 从候选注意力机制到架构研究的证据要求

### 12.1 是否需要完整大模型预训练与后训练

不必在最初阶段完整跑完大模型流程。受控机制实验、小模型训练与严谨消融已经能回答大量关键问题，也是避免浪费算力的必要步骤。

若论文仅主张一个状态更新机制解决某类干扰问题，可以以机制分析、多规模受控训练和任务迁移为主要证据。若主张通用新 Transformer 架构，应补充从头训练、规模与长度扩展、一般能力回归、真实训练/推理效率及实际场景结果。

成熟模型适配可以验证可迁移性，但原骨干能力、保留的完整注意力层和适配方法都会影响结果。它不能单独证明新架构从头训练更优。只有提出后训练或对齐能力主张时，才需要针对性加入对应的 SFT/偏好优化实验；不必为了形式完整先重复整套流程。

### 12.2 值得形成论文的论证链

| 论证项 | 需要交付的证据 |
|-|-|
| 问题存在 | KDA 自身在受控条件和目标场景中的可复现失败 |
| 机制相关 | 改变写入几何、分配或修订路由，能因果影响对应错误 |
| 方法独立 | 区别于 PKDA/QED/SDM/GSA2/HLA 等近邻的具体机制 |
| 预算公平 | 完整持久状态、参数、训练量与实际时间的透明对照 |
| 效果可靠 | 多随机种子、匹配测试实例、不确定性区间和分项结果 |
| 实际意义 | 正确更新、任务成功、少重读或更低成功任务成本 |
| 边界明确 | 容量溢出、相似地址、别名、更新密集和分布变化下的失效 |

“使用相同 tokens”不自动等于相同 FLOPs或训练时间；“状态不随长度增长”不自动等于与纯 KDA 同显存；“保存了 KV”不自动等于答案正确；“跳过旧记录”不自动等于精确删除。这些应成为论文和实验报告的基本表述约束。

### 12.3 建议保留的研究记录

每次实验记录代码提交、数据版本与校验、随机种子、模型配置、训练 token 数、上下文长度、状态精度、实际吞吐、峰值显存、累计 GPU 小时和评测脚本。记录选型失败与反例，而不是只保存胜出分数。

目前所有候选路线均未取得新实验结果。下一阶段最有价值的交付，是一份明确指出“哪一种 KDA 失败能够被哪一个机制在何种预算下缓解”的证据报告，而不是先宣布一个新架构。

# SteadyMem 实验设计

整理日期：2026 年 10 月 13 日。

**当前状态：设计尚未执行。本文没有 SteadyMem 的新算法实现、训练结果、吞吐实测或验收结论。** 下述规模、预算、阶段目标和停止条件用于组织后续研究；引用论文的结果不能作为本项目已经取得的结果。

本文承接《KDA 有限记忆的选择性维护》原稿的实验部分及后续审查。项目应先证明问题，再选择机制。A、B、C 均是候选路线；B 只有在等预算诊断支持记忆组织问题后才值得优先投入，不能预先当作胜出方案。

当前范围与主指标以 [项目定义](PROJECT.md) 为准，路线机制见 [路线评估](ROUTES.md)，判断变化见 [决策记录](DECISIONS.md)，原稿保存在 [revision 12 快照](sources/feishu-kda-rev12.md)。历史版本问答、多跳推理和复杂来源冲突属于后续扩展；本文保留其边界实验，不要求第一阶段同时解决。

## 1. 要回答的研究问题

当未来问题尚未出现、模型持续接收信息时，在固定的总持久状态字节内，能否使新增关联可用、合法修订生效，并保持其他仍有效的关联？

实验须回答三个不同问题：

1. KDA 在目标负载下究竟因写入干扰、衰减、容量、读取、修订识别还是推理失败而出错？
2. 候选机制是否在相同预算内解决了对应问题，而非增加状态、减少更新力度、增加训练或使用未来问题？
3. 改善是否能转化为自然语言与工具任务的联合成功率、少重读或更低的成功任务成本？

以下表述分别使用不同证据口径：

| 口径 | 含义 |
| --- | --- |
| 已有论文证据 | 原论文在其特定架构、模型规模和任务中的结果；不直接推广到 KDA 或本项目 |
| 研究假设 | 候选机制可能解决的失败及其预期收益，待验证 |
| 诊断上限 | 正确地址、理想路由或正确依赖等 Oracle 干预，只用于定位可达上限 |
| 暂定项目目标 | 用于讨论投入规模的数字，须在开发集诊断后重审并在正式测试前冻结 |
| 本项目实证 | 只有实际完成实验、记录配置和原始结果后才可使用该称谓 |

## 2. 所有比较共同遵守的协议

### 2.1 固定总持久状态字节

主要等预算实验固定每请求用于保留历史的总持久状态上限 `B_total`。所有层、所有头、所有预分配槽都计入，空闲槽不能从预算中扣除。按真实张量形状和 dtype 计字节，不能只比较标量数，也不能把 FP32 状态与 BF16 KV 当作相同大小。

必须公开状态账本：

| 状态类别 | 必须计入的内容 |
| --- | --- |
| 主递归状态 | 全部矩阵、卷积历史、归一化所需的持久累积量 |
| 保护与路由 | 地址、原型、探针、优先级、计数器、路由索引、协方差或预条件状态 |
| 多 bank 管理 | 所有 bank、父子或重定向关系、合并与淘汰所需的持久备份 |
| 历史块 | 仿射转移、路由代表、依赖图、当前块必要缓冲、合并摘要 |
| 精确缓存 | 全部 K/V、缓存位置、选择分数及相关元数据 |
| 外部记忆 | CPU/SSD 上的原文、结构化记录、向量、检索索引、来源与时间信息 |

共享模型权重不属于每请求历史状态 `B_total`，但模型参数、权重显存和训练成本须另报。训练激活、算子临时工作区及服务峰值显存也须另报，不能以“持久状态相同”代替“整机显存相同”。外部记录不是免费资源。

新方案消耗地址或管理状态时，基线可将相同总预算全部用于普通 KDA 状态。所谓“扩大 KDA”是扩大到与候选方案相同的总字节上限；候选方案不能同时保留原主状态和免费增加辅助状态。受维度、对齐约束无法精确匹配时，报告实际字节和未用预算，在共同预算附近补充质量—字节曲线。

### 2.2 分别控制训练 tokens 与训练 FLOPs

固定 tokenizer、骨干、数据来源、数据顺序、训练窗口和评测样例，给各方法相同的合理调参机会。参数匹配不能替代其他资源匹配。

必须分别报告两组训练对照：

- **同训练 tokens：**比较相同数据暴露量下的质量，公开新增算子的计算和 GPU 时间。
- **同训练 FLOPs：**在共同训练计算上限内比较质量；若不同方法因此使用不同 tokens，如实记录差异。

真实训练 FLOPs 应包括新增路由、保护求解、teacher、辅助损失和激活重算等。相同参数与 tokens 不自动意味着计算相同；相同 FLOPs 也不自动意味着壁钟时间相同。另报总 GPU 小时和实际集群吞吐，不能把理论 FLOPs 当作服务优势。

适配实验须统一原始 checkpoint、适配数据与后训练配方。从零训练和成熟模型适配是两条证据链，分别报告，不能混合解释。

### 2.3 未知未来问题与因果性

历史写入完成后才随机抽取未来问题，问题不参与此前的保护选择、路由、淘汰或依赖构建。可以在训练时用未来任务损失产生梯度，但前向过程只能访问当时的前缀。

块完成后才可供后续查询读取；当前块只允许提供当前 token 的因果前缀，不能读取尚未发生的块内后缀。Oracle 地址、实体归属、版本关系与完整依赖图单列为诊断上限，不能混入实际方法成绩。

保护选择不得利用测试问题分布中的具体实例。除随机问题外，还要单列低频实体、此前从未被查询的事实、未见表达和别名问题，检查是否只是保护了最常被问的内容。

### 2.4 查询使用状态副本

每个问题从同一历史前缀的独立状态副本开始，避免前一个问题及其生成答案改变后一个问题的记忆。修改前与修改后诊断也分别从对应状态副本开始，使用相同问题、解码设置和答案检查。

这些副本是离线评测的实验工具，不是候选方法可访问的额外历史记忆。不得让算法从修改前副本恢复已经丢失的信息。部署测量单列评测复制开销，并确保每个实际请求的算法持久状态仍受 `B_total` 约束。

## 3. 数据构造与配对事件流

机制数据由程序化状态机记录实体、属性、值、来源、修改关系和有效时间，生成当前值及指定时点的历史值。使用随机编号和不可由常识补全的值，避免依靠参数知识猜中答案。

第一阶段使用无歧义的实体与明确更新，先验证保存和修改规则；第二阶段引入别名、同名实体、自然语言改写、来源冲突、计划与假设、引用旧值、局部撤销、二次修订及乱序到达。消息到达顺序与事实生效时间不同的样例单列，不能把“最后出现”自动定义为“当前有效”。

配对前缀保持实体数、值的信息量、主题分布、长度和填充材料一致，只改变一个待诊断因素。例如：

| 配对事件 | 当前项目 A 的正确答案 | 诊断作用 |
| --- | --- | --- |
| 首次收到 A 的账号为 7319，此前没有该关联 | 7319 | 必须保存新增信息，排除仅保旧而不接收新信息 |
| A 原账号 7319，明确停用并启用 9173 | 9173 | 必须合法覆盖 |
| A 原账号 7319，项目 B 改为 9173 | 7319 | 相似内容不应错误覆盖 A |
| A 原账号 7319，仅讨论是否更换为 9173 | 7319 | 计划不等于生效更新 |
| A 已改为 9173，后文引用旧账号 7319 | 9173 | 引用旧值不应回滚当前值 |
| A 已改为 9173，问题指定修改前时点 | 7319 | 检查历史查询，而非统一拒答旧值 |

独立改变活跃事实数、事实与问题距离、无关 token 数、事实信息熵、地址相似度、更新次数、更新链长度和查询频率。增加长度不能同时默默增加事实数；增加负载也不能同时改变全部查询难度。加入低负载、近正交、高密度随机事实、频繁更新和跨实体整合等明确失效区间。

训练、验证、测试使用分离的随机种子、实体集合和生成模板。另留未见表达、事实密度、修改操作及长度组合。自然语料按文档划分并去重；公开测试题、答案与其改写不能进入训练。课程可逐步增加长度并混入自然文本，但课程实例须独立生成。

生成器真值仅用于监督、评分与 Oracle 诊断。除明确标注的结构化应用基线外，生成器实体 ID、版本表和正确依赖不能留在运行时状态里替模型完成绑定。可靠元数据实验与模型自行抽取元数据实验分开报告。

## 4. 先定位 KDA 的失败机制

先使用已有或冻结的 KDA 模型做配对诊断，再决定是否训练新机制。约 100M 的受控模型可以用于复现，但须先确认它在短上下文、完整正确证据条件下能完成目标任务。小模型复杂问答接近随机水平时，不应把问题直接解释为记忆不足。

| 失败分类 | 具体表现 | 配对干预与控制 | 解释边界 |
| --- | --- | --- | --- |
| 写入干扰 | 合法写入或修改 B 后，此前正确的无关 A 变错 | 固定事实数、距离和衰减，只改变后续写入与 A 地址的重叠；比较重叠、正交与范数匹配控制 | 内部几何干预仅为因果诊断，须再用正常输入复现；召回下降本身不等于 collateral |
| 衰减损失 | 低竞争条件下，旧关联随距离减弱 | 固定活跃事实数与信息量，改变距离；诊断性固定/取消遗忘门并与正常门比较 | 取消门有分布变化；不能把它的诊断结果当作可部署防遗忘方案 |
| 容量或组织 | 同长度下增加独立事实数，召回和可编辑性下降 | 固定距离，扫描负载；比较同字节普通状态与静态分区，先估计分流上限 | 多 bank 不自动增加容量；分区收益与额外状态须分开 |
| 读取失败 | 实际 query 失败，但状态内信息仍能被诊断性读取 | 实际问题与独立训练的读取探针、已知写入方向探针作对照，测改写 query | 成功探针支持信息仍可访问；探针失败不能证明信息已不存在；测试答案不得用于训练探针 |
| 修订识别失败 | 错把相似实体、计划、引用当更新，或未绑定别名 | 给相同读者完整新旧证据，配对真假更新与别名；再比较缺少修订证据的情况 | 完整证据下仍识别错误时，不能用存储或路由缺陷解释全部错误 |
| 必要修订漏读 | 找回了旧证据，但跳过使旧证据失效的后续块 | 在块路由条件下比较普通选块、补最近块、完整后继与理想依赖闭包 | 需先证实独立漏读机制，不能预设 HLA 或所有 KDA 都存在同样问题 |
| 推理失败 | 正确证据已到达，结论仍错误 | 给相同 reader 完整正确证据，固定解码与推理预算 | 若短任务及正确证据条件都失败，先处理读者能力，不能继续堆记忆组件 |

[How Linear Attention Remembers](https://arxiv.org/html/2609.33093) 在 GLA/GDN 中区分了 retention、editability 和 collateral。其第 4 节报告的 GDN 非目标破坏较低，而负载上升仍明显损伤召回。这提醒本项目先测 KDA 自身，不能把别的架构的失效比例直接用于选择 A，也不能把一个指标当作所有记忆问题的替代。

路线选择依赖诊断证据：显著写入副作用且存在可分离方向才支持 A；明显负载竞争且等字节静态分流已有上限收益才支持 B；旧证据可检索、必要修订却漏读才支持 C。主要错误来自读取、绑定或推理时，应重定义研究问题，不能预先坚持某条路线。

## 5. 指标与统计口径

### 5.1 正确更新与保持必须同时成功

主指标与 [项目定义](PROJECT.md) 一致。每个 episode 包含新增关联、合法修订和未更新关联；历史处理结束后提出查询集合 `Q_new`、`Q_update`、`Q_keep`。**JointAcc 是三组查询全部满足当前真值的 episode 比例**：

\[
\operatorname{JointAcc}=\frac{1}{N}\sum_{e=1}^{N}
\mathbf{1}\!\left[\forall q\in Q_{e,\mathrm{new}}\cup Q_{e,\mathrm{update}}\cup Q_{e,\mathrm{keep}},\ \hat a(q)=a^*(q)\right].
\]

三组查询各自数量在比较前固定；跨数量实验按数量分层，不能直接将不同大小的查询集合当作同难度。每个问题独立从同一前缀状态副本读取。真假更新负例也检查正确当前值；不能把所有出现新数字的样例都当作必须改写。

补充事件指标时，对一次新增或修订事件 `j`，记目标为 `t_j`，无关事实集合为 `P_j`，测目标与无关事实同时正确的比例。事件指标用于定位原因，不能替代 episode 主指标。

| 指标 | 定义与要求 |
| --- | --- |
| JointAcc | episode 中固定数量的 `Q_new ∪ Q_update ∪ Q_keep` 全部正确的比例，主指标 |
| NewAcc | 新增关联的当前值准确率，防止以拒收新信息换取保持 |
| TargetAcc | 目标当前值正确率；真实更新与无需更新的负例分别报告 |
| KeepAcc | 未更新关联当前值准确率，包含低频及未见改写 |
| HistoricalAcc | 后续扩展中的指定时点历史值正确率；与当前值准确率分开 |
| EventJointAcc@p | `目标当前值正确 AND 固定数量 p 个无关事实全部正确` 的事件比例；`p` 在实验前确定，各负载相同 |
| EventJointAcc@All | `目标正确 AND 本事件全部待检查无关事实正确`；更严格事件补充，不能与不同事实数条件直接当作同难度比较 |
| NonTargetBreak | 此前正确的非目标事实中，修改后变错的比例：`#(before正确且after错误) / #(before正确)`；分母和绝对数量必须报告 |
| OldValueError | 当前值问题中回答过期值的比例；真实更新和错误覆盖负例分别报告 |
| Coverage / Abstention | 回答覆盖率、拒答率及拒答正确性；不能靠拒答降低旧值误答率并称任务成功 |
| Recall / EffectiveCapacity | 全体事实召回；在预先定义准确率门槛下能稳定处理的独立事实数，门槛只用于可控任务 |
| Evidence / Routing | 证据保留、正确读取、必要修订召回；只能辅助解释，不能替代答案与任务成功 |

`JointAcc` 和事件联合指标使用答案正确性，不以状态变化小或预测概率不变替代。无关事实集合的抽样协议在实验前确定，评测真值不传入算法。另报全部事实的准确率，避免只挑保护覆盖内的简单问题。

`NonTargetBreak` 按每个方法自身修改前正确的集合统计，同时报告基线与候选共同正确的固定配对集合，以及未经条件筛选的总体准确率，避免候选通过更差的初始记忆缩小分母。不得只保留修改后仍正确的样例。

### 5.2 排除“写得更少”的伪保护

路线 A 在相同目标拟合误差或目标更新成功率下比较非目标破坏，绘制目标成功—非目标损伤曲线。以 `s = k^T u` 记方向响应，其局部目标拟合比例为 `eta*s / (1+eta*s)`；增大保护强度会降低它，因而单看损伤减少不足以证明保护有效。

加入简单降低 KDA 更新强度的对照。匹配参数只在开发集选择；不能在测试集逐样例调整以得到有利结果。机制层报告目标残差、非目标读出扰动、更新范数、状态范数和梯度；语言层仍以实际答案与 `JointAcc` 检验，不能把局部回归拟合当作最终回答保证。

### 5.3 多种子与不确定性

涉及训练的机制层、340M 系统层及用于主要结论的核心比较至少 **3 个独立训练随机种子**。每个种子使用相同配对测试实例，报告均值、种子间变化、配对置信区间和失败案例。数据生成 seed 与训练 seed 分开记录；大量测试实例不能替代独立训练种子。

冻结已有模型或纯状态矩阵的诊断不要求为此重训模型。此类实验使用独立生成 seeds 和相同配对实例，如实记录 checkpoint、权重版本及可用的模型种子；生成种子的稳定性不能表述成独立训练种子的稳定性。

涉及同一来源、实体或对话的多个问题时，按来源或实体聚类进行配对 bootstrap，避免将相关问题当作完全独立样本。报告绝对变化及错误率分母，再报告相对变化。样本量依据开发集方差与预先设定的最小可检测效果确定。

1.3B 或成熟模型的单种子运行只可作成本与可行性 pilot，不能形成稳定胜出的最终结论。若资源只允许单种子，明确收缩主张，不隐去这一限制。

| 0：任务与实现核验 | 程序真值、短上下文 reader、冻结 KDA、逐 token 参考 | 真值一致、短任务可解、无未来泄漏、预算账本 | 排除题目与读者能力缺陷，再做机制比较 |
| 1：机制层 | 约 100M 模型、可控随机关联、真假更新、负载与几何扫描；冻结诊断用独立生成 seeds，涉及训练的核心比较至少 3 训练 seeds | KDA 的可复现失败区间、配对因果证据、Oracle 上限与实际因果策略差距 | 对应机制有等字节、匹配目标成功率的收益；无关事实与合法更新同时受益 |
| 2：系统层 | 340M、15B tokens 作为原稿起始配置；单路线、关键消融与成本曲线；至少 3 seeds | 同 tokens 和同 FLOPs 的独立比较，`JointAcc`、一般能力回归、真实吞吐 | 稳定胜过强基线，收益有明确来源且非广泛退化换单项分数 |
| 3：规模或适配 | 仅胜出方案进入 1.3B/100B tokens，或成熟模型适配；不默认两者全做 | 可迁移性、长度与负载扩展、完整成本、至少一个应用场景 | 验证质量收益能够转化为任务成功或成功任务成本 |

上述参数和 tokens 是实验规划起点，尚未运行，不代表这些配置已经可训练或足够。不要在第一阶段同时加入 A、B、C；先独立验证，再考虑组合交互。有限精确 KV 也只在诊断确认需要精确访问后加入。

质量评测前，后续实现须验证逐 token 参考、分块训练和增量解码的前向与反向一致性，并覆盖跨块更新、淘汰、批处理重排和状态回滚。若训练使用连续路由、推理使用离散路由，单列转换损失。本文只规定这些未来检查，没有执行代码、测试或训练。

## 7. 强基线及其公平比较方式

机制和系统实验先选最接近失败类型的少量强基线，不用弱配置制造优势；胜出后再扩展质量—资源曲线。跨论文分数不能直接排名。

| 对照 | 要排除的解释与预算要求 |
| --- | --- |
| 纯 KDA、同总字节扩大状态的 KDA | 增益是否只是辅助状态带来的容量；公开实际 dtype 与全部层状态 |
| 降低更新强度的 KDA | A 是否只是写得更少；匹配目标成功率或拟合误差 |
| [PKDA](https://arxiv.org/html/2604.21100)、[Diagonal KDN](https://arxiv.org/html/2609.07816)、[Gated KalmaNet](https://arxiv.org/html/2511.21016) | 历史曲率、不确定性或二阶回归能否解决同样问题；协方差、辅助状态和求解计算全部计入 |
| [GDN2](https://arxiv.org/html/2605.22791)、[QED](https://arxiv.org/html/2608.13668)；必要时加入 [EDA](https://arxiv.org/html/2606.26560) | 擦写解耦及 query 相关清理是否已经达到相同收益；统一骨干与训练配方 |
| 同字节静态 bank、hash、随机、最近路由 | B 的组织与干扰信号是否有独立收益；所有预分配 bank 和探针计入 |
| [MoM](https://arxiv.org/html/2502.13685)／MoM-KDA 预算适配 | B 的直接近邻已包含多状态、稀疏路由和非选状态保持；比较内容路由与加入干扰反馈的版本，匹配实际读写数量与总持久字节 |
| [SDM](https://arxiv.org/html/2607.07386)、[GSA2](https://arxiv.org/html/2610.02816) 的预算适配对照 | 稀疏访问和多槽纠错的近邻能力；明确适配改动，不能将同 FLOPs 当作同状态字节 |
| [HLA](https://arxiv.org/html/2610.05842) 的有界历史缓存版本 | C 是否超过普通 query 驱动选块；原方法保留增长的历史块，有界合并/淘汰版本不能冒充原始配置 |
| 有限精确 KV：最近、随机、写入强度选择；[HOLA](https://arxiv.org/html/2607.02303) 适配 | 将相同预算用于精确表示能否更好；缓存选择与额外容量分开检验 |
| [KDA＋MLA](https://arxiv.org/abs/2510.26692)、滑窗注意力 | 改变完整注意力层比例或窗口，在共同历史状态预算内是否更划算 |
| 完整注意力 | 作为信息可用性与质量参照；若完整历史超过预算，明确标为额外资源上限，不纳入等字节胜负 |

应用层必须加入以下强基线，而不能只与纯 KDA 比较：

| 应用基线 | 公平实施与成本记录 |
| --- | --- |
| 有界结构化表 | 固定记录容量，保存当前状态、必要时间和来源，明确满容量淘汰；真值元数据版仅为上限，实际版由模型从相同输入抽取，抽取与维护成本计入 |
| 有界 RAG／原文记录 | 固定总原文、向量、索引及元数据字节，明确淘汰；相同 reader、证据输出和推理预算，报告检索漏读更新与旧值误答 |
| 有限精确 KV | 同总字节的最近、随机和学习选择策略；不能将 KV 表示当作完整语义记录 |
| 短窗口＋摘要 | 摘要容量和生成成本有界；检查摘要是否丢失修订和低频事实 |
| 重新读取工具或原文 | 使用相同可访问工具，计调用次数、延迟、费用与失败率；原始记录和环境访问不视为免费 |

结构化表与 RAG 解决的是应用层记忆管理，不自动证明神经架构创新；但若它们更便宜、更准，就应成为实际部署推荐。应用比较统一输出预算、工具集合、reader、推理预算和服务时限。

## 8. A/B/C 的具体实验与消融

### 8.1 A：少量历史读取地址的保护写入

待验证假设：有限地址覆盖了后续常用读取方向，并且新 key 仍有可分离方向时，约束写入能减少无关关联破坏。

先固定或控制衰减，测写入副作用，再加入真实遗忘门。当前约束保护的是衰减后状态，不能把先前衰减损失算成已经解决。保护旧 key 与保护实际 query 分别检验，加入改写和别名，不能只重复完全相同地址。

必须比较：去掉保护、随机地址、最近地址、因果学习地址、Oracle 地址；固定保护与选择性释放；去掉释放、错误释放；不同保护强度与地址数量。涉及块实现时，比较块内固定银行和逐 token 更新，并报告刚进入块的重要事实是否漏保。离散选择、detach 银行或截断梯度的处理明确记录。

合法更新应释放或降低对应旧保护，相似实体不得误释放。报告目标拟合—非目标损伤曲线、`JointAcc`、保护覆盖内外表现、范数和全部字节；在同目标成功率下比较普通 KDA、简单弱写入、PKDA、Diagonal KDN 与 QED 等近邻。

停止或转向条件：KDA collateral 已接近零；Oracle 等预算且匹配拟合也不优于强基线；收益被弱写入或扩大状态解释；实际选择长期不优于最近/随机；保护造成合法更新退化；强保护在近共线时引起范数或数值问题。Oracle 有效而因果选择无效时，应将问题定位为选择与释放，而非继续扩大预训练掩盖它。

### 8.2 B：固定总预算的干扰分流

待验证假设：等字节下的组织与分流能够降低竞争损失。先做静态 bank 与简单路由，再加入干扰项；静态分区未显示可达收益时，不立即叠加 split/merge/淘汰。

必须比较：普通多头 KDA、同字节扩大状态、MoM-KDA、静态 bank、hash/随机/最近路由、因果内容路由、内容路由＋干扰项；匹配实际读写数量，去掉干扰项、固定调度；分别加入分流、合并、淘汰及关系释放。节约下来的容量重新分配实验与直接删除组件实验分开。

干扰分数不能把大 delta 残差自动当作破坏，也不能惩罚合法修改目标关联。探针覆盖内外都测，比较随机、最近和学习探针。使用已知实体归属的 Oracle 路由只作上限，推理时不得保留生成器实体表替代学习绑定。

固定长度扫描事实数与主题交错，单列低频实体、跨区整合和未来才重要的内容。split 先仅分流未来写入；不能声称已压缩事实可以无损拆开。合并/淘汰前后对同一组保留事实作配对查询，记录失真、`JointAcc`、重定向表容量和悬空关系。所有空闲 bank、探针与备份计入预算。

停止或转向条件：等字节收益消失；实际路由不优于 hash；只能靠更多总状态获益；分流收益被合并损伤抵消；低频或跨区事实明显退化；关系表或备份必须持续增长。此时应收缩为容量扩展或机制诊断，不能继续宣称同预算组织优势。

### 8.3 C：读取历史时保留必要修订依赖

待验证假设：普通选块能够找到旧证据却遗漏必要后继，依赖闭包可以降低这类错误。先用理想依赖图验证反例和上限，再学习依赖识别；不能先假定路由漏修订是主要错误。

必须比较：普通 HLA 式选块、去掉依赖闭包、同实际读取块数的 top-k、补最近块、保留全部后续转移、固定槽内全读，以及同总字节下维护当前/历史双表示的简单对照；Oracle 依赖与因果学习依赖；不同误报/漏报率、依赖链长度和合并粒度。各对照获得相同训练样例，避免把更多修订监督当成架构收益。

加入旧证据易匹配而新修订难匹配、二次修订、同名实体、计划与引用负例、历史时点问题和无关事实保持。报告必要更新召回、旧值误答、`JointAcc`、历史准确率、闭包大小、全读回退率和合并前后失真。

固定槽数不等于同 KDA 字节。双矩阵块摘要、当前块、依赖图、合并备份全部计入；满容量合并后失去区间内部选择性，截止时点落在合并区间内时应明确可支持的历史粒度。闭包超过读取预算时回退固定槽全读，不得再截掉必要修订并称保持一致性。

停止或转向条件：Oracle 图也无收益；完整证据下 reader 仍不理解修订；学习图近全连接并频繁全读；补相同数量普通块已经达到相同效果；合并丢失历史粒度；结果只表现为拒答旧值而新值也记不住。

固定旧摘要重组不等价于记录从未出现。[Exact Record Omission](https://arxiv.org/html/2609.06872) 区分了行为不再回答与恢复 never-stored 状态；本项目此阶段只检验行为与修订一致性，不主张精确删除。

## 10. 服务性能与完整成本

分别测预填充与解码、单请求与高并发。固定硬件、dtype、输出长度和服务时限，公开 batch 与并发，不能把候选的大 batch 吞吐与基线的 batch 1 延迟混比。

必须报告每请求持久状态字节、峰值显存、训练 tokens/FLOPs/GPU 小时、TTFT、TPOT、p50/p95 延迟，以及满足正确性和服务时限的有效吞吐。路由扫描、地址求解、历史合并、依赖闭包和全读回退均计入；只选择少量块之后便宜，不意味着寻找这些块免费。

应用价值使用“每成功任务成本”：总 GPU 时间或总费用除以满足正确性与服务时限的成功任务数。同时公开失败率、工具重读次数和外部存储/访问开销，避免用拒答减少费用制造表面优势。

## 11. 暂定目标与通用停止条件

原稿中的数字保留为待重审假设，不作为效果承诺、行业标准或已经达到的门槛：

| 原稿暂定目标 | 重审要求 |
| --- | --- |
| A：匹配目标更新成功率后，非目标破坏相对减少 30% | 必须先有足够大的绝对破坏率，且 `JointAcc` 与总体召回不退化；10% 到 7% 才是相对减少 30%，不是准确率增加 30 个百分点 |
| B：在召回至少 90% 的定义下，有效容量约为基线 1.5 倍 | 仅用于可控任务，须等总字节，单列低频与跨区表现；不预设 B 应达成该值 |
| C：旧值误答相对减少 50%，平均读取不超过 J/4，全读回退不超过 10% | 新值、历史值和无关事实都要保持；读取预算及回退成本不能隐藏 |
| C 等回归项不下降超过 1 个百分点 | 需依据开发集方差、任务价值和置信区间重审，不能把单点差作为可靠结论 |
| 同预算任务平均改善 3 个百分点，或同质量字节减少 20% | 是讨论投入的候选门槛；与 `JointAcc`、一般能力和真实成本共同评估 |

先用开发集确定基线错误规模、最小可检测效果、应用成本与统计功效，再冻结正式测试标准。不得看完测试结果后改变容量定义、查询分布或门槛。

通用停止或转向条件：

- 任务真值或短上下文 reader 未通过核验，先修任务或读者。
- 主要失败来自修订理解、读取或推理，当前写入/分流机制与问题不匹配。
- 等字节或匹配目标更新成功率后收益消失，或收益由更多训练解释。
- 强基线、简单 hash、弱写入、有限 KV 或补最近块解释了全部收益，停止将该组件作为独立创新。
- Oracle 有效但实际因果识别长期无效，收缩到辅助选择问题，不扩大训练掩盖它。
- 容量、关系链、备份或外部记录必须增长，重新定位为容量扩展而非固定记忆优势。
- 合法覆盖、低频实体、未见改写、历史查询或一般能力出现实质退化。
- 原型有效但高效实现未形成合理吞吐，分开报告算法证据与工程限制。
- 有界结构化表、RAG、有限 KV 或重读工具更便宜且更准确，将其作为实际推荐。

## 12. 8 张 H100 条件下的资源规划

8 张 H100 80GB 是资源条件；2026 年 10 月 13 日 17:03:23（Asia/Shanghai）已只读核验硬件和共享路径，检查时仍有占卡进程，详见 [算力环境](ENVIRONMENT.md)。这些盘点不是 SteadyMem 的训练吞吐实测、可用计算配额或完成日期。后续应先确认实际可用 GPU、训练框架、互联、显存、数据装载和算子状态，再定运行计划。

全参数 dense 训练可先以 `F ≈ 6ND` 估算骨干计算，`N` 为参数量、`D` 为训练 tokens。新增注意力、路由、求解、teacher 和重算另计；冻结骨干或 LoRA 不能只按可训练参数估算全部成本。

下面沿用原稿每卡持续有效计算 100–250 TFLOP/s 的**规划假设**，不是本机实测。1 GPU 小时表示一张卡运行一小时；8 卡时间假设理想摊分，尚未计通信、算子与其他工程损耗。

| 单次配置 | 骨干粗估计算 | 粗估 GPU 小时 | 8 卡理想时间 |
| --- | --- | --- | --- |
| 340M，15B tokens | 30.6 EFLOP | 34–85 | 约 4.3–10.6 小时 |
| 1.3B，100B tokens | 780 EFLOP | 870–2,170 | 约 4.5–11.3 天 |
| 已有 7B，全参数适配 1B tokens | 42 EFLOP | 47–117 | 约 5.9–14.6 小时 |

这些数字仅为条件粗估，不能据此声称本项目训练可在相应时间完成。[NVIDIA 官方性能说明](https://github.com/NVIDIA/exemplar-performance) 的峰值也不能代替持续有效吞吐；带稀疏条件的峰值不能直接代入普通 dense BF16 训练。

原稿研究总预算同样是尚未实测的示例：

| 阶段 | 原稿粗预算 | 使用条件 |
| --- | --- | --- |
| 机制原型 | 50–200 GPU 小时 | 约 100M、多负载与更新压力，训练核心比较至少 3 训练 seeds，冻结诊断用独立生成 seeds；先证明问题与机制 |
| 340M 筛选 | 500–1,800 GPU 小时 | 少量核心配置各至少 3 seeds、关键消融与评测；更广扫描另计 |
| 规模与场景 | 2,000–8,000 GPU 小时 | 少数胜出配置的 1.3B 或成熟模型适配；不默认覆盖所有组合 |

合计 2,550–10,000 GPU 小时、理想占满 8 卡约 13–52 天，均是原稿预算示例，不是运行记录或日历承诺。独立种子、长窗口课程、应用评测、调参和失败重跑须重新计入。

真正排期之前，应在实际机器上为原生 KDA 与候选算子测 200–1,000 个稳定 step，包含真实长度、优化器、checkpoint、数据装载和分布式通信。再以总训练 tokens 除以实测集群 tokens/s 估算壁钟时间，单列评测预填充与工程开发。逐 token 原型速度不能直接外推最终融合实现。

原稿 A 约 2–4 周、B 约 3–6 周、C 约 4–8 周的开发预留，也只在已有训练框架的条件下作为粗规划。优先完成机制证据与资源核验；没有独立收益时不进入昂贵预训练，更不默认先完整重做 SFT 与 RL 流程。

## 13. 后续实验必须留下的记录

每次正式比较保存任务生成版本与 seeds、数据划分、模型/checkpoint、tokenizer、训练配方、全部状态形状与 dtype、真实预算、调参范围、前向可见信息、Oracle 标记、实现核验记录、原始逐题答案、配对指标及成本日志。

最终论证链必须依次成立：KDA 的具体失败可复现；对应干预能影响错误；实际因果机制在等预算下有效；合法更新与无关保持同时成功；多种子稳定；收益迁移到自然语言或工具任务；完整成本优于合理替代。任何尚未完成的一环保留为未验证，不用命名、理论复杂度或其他论文成绩代替。

## 14. 五类方法的首轮筛选

本轮候选机制见 [路线文档](ROUTES.md) 第 7 节。下表补充筛选问题，不启动实现，不冻结最终算法；其余预算、因果性、状态副本和 JointAcc 协议保持适用。

| 方法 | 最小诊断 | 必要对照与停止信号 |
| --- | --- | --- |
| 稳定语义地址 | 实际/Oracle 地址 × 实际/Oracle 修订门，保持值支路和更新规则；配对改变值、实体、属性、别名与真假更新 | Oracle 只作定位；Oracle 无收益不投寻址，实际方法只在重复措辞有效则未解决泛化绑定 |
| 完整一步更新保护 | 低/高键重叠 × 无/有衰减，区分写入与整步损伤 | 同目标成功率下比较弱写入、仅写入保护、完整保护与 PKDA/KDN；增益只来自少写或成本不值得时停止 |
| 干扰感知分流 | 固定 bank、固定总字节和读写数量，内容候选中比较有限反馈 | MoM、hash、仅内容及负载均衡；修订写到别处留下旧值为失败；静态反馈不过关不加 split/merge |
| 有效性遗忘 | 独立扫描真实变更率、同值确认率和未来查询频率；加入低频关键事实与慢区突然修订 | 同样语义监督的原 KDA、单状态有效性控制与快慢分区；更久保存造成过期值更多或错误迁移时停止 |
| 当前值覆盖槽 | 让活跃关联数跨过固定槽容量，强制淘汰修订槽，加入二次修订与低匹配改写 | 同字节更大状态、HOLA、最近缓存、有限当前值表及 RAG；淘汰后旧值复活、拒答或重读消耗优势时收缩主张 |

冻结模型与纯状态诊断先采用独立生成 seeds；涉及学习的核心结论仍遵守至少 3 个训练 seeds。地址/操作标签仅用于训练或明确标注的 Oracle 诊断，不进入普通方法前向。

补充精度预算对照：[DAMP](https://arxiv.org/html/2608.27513) 等递归状态量化方案要统计尺度、通道索引、随机舍入与转换的开销。当前规模量化与重新训练更大维度的同字节状态分别评价；不能把降低存储精度直接当作免费增加语义容量。
